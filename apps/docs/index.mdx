## The short version

An agent can pay for things on Cardano with **x402**: it asks for a resource, gets a price, pays, and gets the resource. With the escrow payment method, the money is locked on chain instead of going straight to the seller.

But x402 stops at the lock. Once the money is in escrow, nothing makes sure the buyer gets what it paid for. If the seller never delivers, or delivers the wrong thing, someone has to notice and act before the deadlines pass. An agent has no human watching.

**Simpuru is that someone.** It is a shop for design prompts where every purchase can be protected: the seller commits to exactly what they sell before they are paid, the delivery is checked against that commitment, and the buyer gets the money back automatically when it does not match.

<CardGroup cols={2}>
  <Card title="Sellers commit first" icon="fingerprint">
    Every listing carries the SHA-256 hash of what it sells. The escrow is bound to that hash before anyone pays.
  </Card>
  <Card title="Pay into escrow" icon="lock">
    A protected purchase locks the payment on chain. The seller only gets it after the delivery checks out.
  </Card>
  <Card title="Refunds happen on their own" icon="rotate-left">
    No delivery by the deadline means a refund. A delivery that does not match means a dispute. No human has to notice.
  </Card>
  <Card title="Disputes are settled by evidence" icon="scale-balanced">
    An arbiter pays the seller only if the delivered content is provably the one listed. Otherwise the buyer is paid back.
  </Card>
</CardGroup>

## At a glance

| | |
| - | - |
| Network | Cardano preprod (test ADA only) |
| Payments | x402 v2: `default` (instant) and `masumi` (escrow) |
| Escrow | Masumi `vested_pay` V2 validator, unchanged, deployed with Simpuru's own arbiter key |
| What is sold | Design prompts: paste one into a coding agent and it builds a page |
| Who can sell | Anyone signed in with a Cardano wallet |
| Who can buy | People on [app.simpuru.xyz](https://app.simpuru.xyz), and agents over MCP |
| Status | Live on preprod. Every claim in these docs links a preprod transaction |
